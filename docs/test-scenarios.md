# Сценарии приемки qadam

Сценарии проверяют наблюдаемое поведение. Они не являются заявлением, что каждый ручной тест уже выполнен. Автоматические проверки запускаются через `npm test`. Демонстрационные погодные режимы дают воспроизводимые условия.

Для каждого сценария фиксируйте дату, версию каталога, фактический режим генерации, полученные POI и результат. Проверяйте итоговые карточки, а не только текст ответа модели.

| № | Вход и действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Район Экспо, 60–90 минут, зимний режим −25 °C, «погреться и посмотреть интересное» | До 3 подходящих помещений. Видна маркировка демо-погоды и погодное предупреждение. Нет обещания безопасного перехода между зданиями |
| 2 | Летний режим, «спокойно погулять на свежем воздухе» | Открытые места участвуют в подборе. Для каждой рекомендации есть причина, примерная длительность и действия |
| 3 | Тот же запрос и район, уменьшить свободное время | Подбор учитывает новый лимит. Место, для которого очевидно не хватает времени с учетом принятой модели, не должно занимать верхнюю позицию без объяснения |
| 4 | Запрос «уютное место с историей» и старт на Правом берегу | Исторические или культурные теги повышают релевантность подходящих записей. Система не выдумывает историю заведения |
| 5 | Отказать браузеру в геолокации, выбрать район | Основной подбор работает. Понятно, от какой точки считаются расстояния. Координаты не появляются в localStorage |
| 6 | Разрешить геолокацию по кнопке | Пользователь видит состояние запроса и понятную ошибку при недоступности. Точка используется для текущего поиска, история перемещений не создается |

| 9 | Отключить API-ключ и повторить обычный запрос | Работают поиск и фильтры. Интерфейс явно сообщает шаблонный режим, без заявления о выполненном вызове LLM |
| 10 | Задать недействительный ключ либо имитировать ошибку провайдера | Понятный fallback на шаблон. UI не зависает и не раскрывает секретный ключ или внутренние сообщения провайдера |

## Техническая приемка

После установки зависимостей выполните `npm test`, `npm run check` и `npm run build`. При запущенном сервере выполните `npm run smoke`. В ручной проверке пройдите как минимум сценарии 1, 2, 5, 7, 8, 9 и 14. Вызов реального LLM с действующим ключом проверяйте отдельно: успешная сборка и шаблонный демо-ответ его не подтверждают.

Автоматические тесты должны проверять существенные границы: фильтр погоды, отсутствие неизвестных POI в ответе, ограничение числа рекомендаций, обработку некорректного ввода и fallback при сбое модели. Число тестов и результаты указывайте только после фактического запуска.

На этапе подготовки 18 октября 2026 года выполнены 16 автоматических тестов, проверка типов и smoke-проверка API. Реальный оплачиваемый вызов LLM с действующим ключом не выполнялся. Тесты LLM используют подставные ответы и ошибки сети. Итоговую сборку и ручной прогон перед сдачей следует повторить командами выше после последнего изменения кода.
