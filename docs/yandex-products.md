# Выбор продуктов Яндекс Карт для Seruen

Проверено по официальным источникам 18 октября 2026 года. Это сравнение для выбора продукта, а не подтверждение активации ключа или права проекта на бесплатную лицензию. Yandex API в код приложения этим документом не подключается.

Для веб-сайта Seruen первым кандидатом является **JavaScript API**: интерактивная карта, собственные маркеры, элементы управления и слой пробок. Геокодер нужен отдельно, если пользователь будет вводить адрес, а Геосаджест — если нужны подсказки при вводе. Сейчас Seruen уже располагает координатами POI и стартовых ориентиров, поэтому подключать все продукты сразу не требуется. Назначение продуктов и доступные варианты отражены в [официальном каталоге и тарифах](https://yandex.ru/maps-api/tariffs).

## Продукты из списка подключения

В таблице указан подтвержденный бесплатный лимит при соблюдении применимых условий. Создание бесплатного ключа само по себе не означает бесплатное использование любого продукта.

| Продукт | Для чего нужен | Бесплатный режим и единица учета | Выбор для Seruen |
| --- | --- | --- | --- |
| JavaScript API | Интерактивная карта на сайте | Показ карты доступен в бесплатном режиме по условиям. Панорамы — до 100 вызовов в сутки. Новому ключу нельзя приписывать прежний общий пакет 25 000 вызовов всех сервисов | Основной кандидат для веб-карты |
| Static API | Изображение фрагмента карты | До 100 запросов в сутки. Запрос возвращает статичное изображение, а не интерактивную карту | Не заменяет перемещение и масштабирование в текущем интерфейсе |
| MapKit SDK | Карта в мобильном приложении | До 1 000 DAU в сутки. Учитываются пользователи, открывавшие карту, а не HTTP-запросы тайлов | Для будущего мобильного приложения, не для React-сайта |
| Tiles API | Растровые тайлы для собственного картографического клиента | До 30 запросов в секунду. Это ограничение скорости, его нельзя читать как 30 запросов в день | Возможен отдельный картографический клиент, но потребуется больше интеграционной работы |
| Получение деталей маршрута | Геометрия и сведения о рассчитанном пути | Постоянная бесплатная квота для нового подключения не подтверждена текущей таблицей. Нужны условия выбранного тарифа или согласованный тестовый доступ | Полезно для следующего этапа реальной маршрутизации |
| Isochrone API | Область, достижимая за заданное время | Постоянная бесплатная квота для нового подключения не подтверждена | Возможное развитие подбора по доступности, не обязательный первый шаг |
| Матрица расстояний | Время и расстояние между множеством точек | Постоянная бесплатная квота для нового подключения не подтверждена. Не следует считать HTTP-пакет бесплатной единицей без проверки его тарифа | Может пригодиться для ранжирования, текущий прототип обходится без нее |
| Геокодер | Адрес в координаты и обратно | До 1 000 обращений в сутки суммарно к сервису. Прямое и обратное геокодирование расходуют лимит | Подключать при добавлении поиска стартовой точки по адресу |
| Поиск по организациям | Поиск и сведения об организациях | Постоянная бесплатная квота для нового подключения не подтверждена. Прежние квоты старых JS-ключей нельзя переносить на новый ключ | Не заменяет разрешенный собственный RAG-каталог автоматически |
| Геосаджест | Подсказки адресов при вводе | До 1 000 запросов в сутки. Подсказки могут вызывать несколько запросов за один ввод адреса, поэтому нужен debounce | Полезная дополнительная функция к вводу старта |
| Локатор | Геолокация по сетевым данным без GPS | Постоянная бесплатная квота для нового подключения не подтверждена | Для обычного выбора старта в браузере достаточно добровольной browser geolocation |

Числа бесплатных лимитов приведены по разделу 6 [условий API](https://yandex.ru/legal/maps_api/ru/#ogranicheniya-ispolzovaniya-otdelnyh-servisov): панорамы — 6.1.2, MapKit — 6.2.3, Static — 6.3.1, Геосаджест — 6.4.1, Tiles — 6.5, Геокодер — 6.6.2. Таблица тарифов показывает также платные пакеты. Их нижняя граница, например 10 000 запросов Static или 5 000 DAU MapKit, не является бесплатной квотой. [Официальные тарифы](https://yandex.ru/maps-api/tariffs).

## Старые и новые ключи

Объявление об изменении тарификации различает ключи, активные на **20 апреля 2025 года**, и JS-ключи, созданные позже. Старым активным ключам в объявлении перечислены лимиты сопутствующих сервисов. Для новых JS-ключей отдельно указан лимит панорам, а прочие сервисы требуют подключения соответствующего продукта. Поэтому предложение «подключить JS и бесплатно получить по 1 000 маршрутов и поисков организаций» для нового аккаунта не подтверждается. [Официальное пояснение изменения бесплатной тарификации](https://yandex.ru/maps-api/docs/news/new-billing/free-usage.html).

Тестовый период платного продукта и постоянная бесплатная лицензия — разные режимы. Возможность и срок теста нужно проверять для подключаемого продукта в кабинете. Получение ключа бесплатно, но использование некоторых API требует оплаты. [Кабинет разработчика](https://yandex.ru/maps-api/docs/developer/index.html).

## Несколько продуктов и общий учет

Один аккаунт может подключать разные сервисы и получать их ключи. Для каждого сервиса требуется подключение и активация. JS, Геокодер и Геосаджест не следует считать одним разрешением только потому, что они используются на одной странице. Например, документация JS API 2.1 предусматривает отдельный `suggest_apikey`. [Порядок работы кабинета](https://yandex.ru/maps-api/docs/developer/index.html), [подключение JS API](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/dg/concepts/load).

Квота конкретного API общая для всех его ключей. Создание второго ключа не удваивает ее. Квоты разных продуктов нельзя складывать в универсальный пул и переносить между сервисами: остаток Геокодера не дает дополнительные запросы маршрутизации. По конкретному ключу необходимо сверить его активированные продукты, тариф и счетчики в кабинете. [Официальное описание учета всех ключей одного API](https://yandex.ru/maps-api/docs/developer/index.html).

Один сайт технически может использовать несколько разрешенных продуктов. Для браузерных ключей нужны ограничения на фактические домены/Referer проекта и отдельные правила локальной разработки. У Seruen текущий домен — `seruen-astana.connect550439.chatgpt.site`. Это не создает новую квоту и не отменяет требований каждой лицензии. Применимость бесплатных условий к конкретному сценарию рассматривается отдельно от выбора продукта.

## Языки для Астаны

В проверенной документации **JS API 2.1** перечислены `ru_RU`, `en_US`, `en_RU`, `ru_UA`, `uk_UA`, `tr_TR`. Казахская локаль `kk_KZ` в этом перечне не указана. Следовательно, нельзя обещать казахские элементы управления и подписи карты только на основании наличия казахского интерфейса Seruen. Для английской карты в метрических единицах предусмотрена `en_RU`. Собственные кнопки, карточки и объяснения приложения могут сохранять казахский язык независимо от локали картографического SDK. [Официальный список локалей JS API 2.1](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/dg/concepts/load).

Это вывод для указанной версии. Его нельзя автоматически переносить на другую версию SDK или другой продукт Яндекса. Поддержка `kk_KZ` в API Погоды не доказывает поддержку такой же локали в API Карт.

## Пробки и балл

В JS API 2.1 есть `control.TrafficControl` и провайдер `traffic.provider.Actual`. Документация описывает `state.level` как балл **от 0 до 10**, а также поля `isInited`, `timestamp` и `isotime`. Это дает документированный способ прочитать состояние провайдера внутри картографического SDK. У Seruen текущая проверка фида и MapGL ожидает 1–10, поэтому возможное подключение Yandex потребует отдельного адаптера шкалы и состояния доступности, а не механического повторного использования прежнего условия. [Состояние провайдера](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/ref/reference/traffic.provider.Actual), [TrafficControl](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/ref/reference/control.TrafficControl).

Публичные документы SDK не являются подтверждением самостоятельного REST-экспорта балла для произвольного backend или другой карты. Доступ через объект SDK, покрытие Астаны, актуальность конкретного значения и допустимый способ отображения необходимо проверять отдельно. Наличие слоя пробок не гарантирует, что балл получен для каждого участка города. Для интерфейса нужно сохранять честное состояние «недоступно» и проверять время данных.

## Предлагаемый первый набор

Для оценки Yandex в Seruen достаточно выбрать **JavaScript API**. Если нужен ввод адреса — отдельно подключить **Геокодер**, а для автодополнения — **Геосаджест**. Static, MapKit, Локатор и серверные продукты маршрутизации не нужны только ради интерактивной веб-карты с уже известными координатами. Это техническая рекомендация для текущего проекта. Подключение API, смена провайдера и отправка данных Яндексу требуют отдельной реализации и проверки условий.
