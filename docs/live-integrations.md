# Карта, актуальная афиша и подключение источников

Состояние реализации проверено 18 октября 2026 года. Название интерфейса: Seruen. Это продолжение только первой задачи хакатона.

## Что уже работает

- Интерактивная географическая карта с перемещением, масштабом, собственными маркерами, выбором места и внешней ссылкой на маршрут в 2GIS. Приоритет провайдеров: Яндекс → 2GIS → Leaflet/OpenStreetMap. SDK и тайлы загружаются после отдельного согласия пользователя.
- Браузерная карта Яндекса настроена через `YANDEX_MAPS_JS_API_KEY` в секретах хостинга; настоящая работа ключа и пробок на домене еще требует браузерной приемки. Показаны собственные POI, явно включены масштаб, полный экран и пробки. Геокодер, поиск, саджест, панорамы и построение маршрута Яндекса не вызываются.
- При `TWOGIS_MAPGL_KEY` резервный MapGL JS SDK включает слой пробок и получает балл через событие `trafficscore`. Яндекс принимает свой балл 0–10, 2GIS — 1–10; число берется из SDK, а не выводится из цвета дорог.
- `POST /api/discover` получает актуальные сеансы и события из разрешенных нормализованных фидов. Если они не настроены, есть адаптеры публичных страниц Киноафиши и официального городского портала Astana.kz.
- В реальном локальном HTTP-запросе 18 октября получены 23 предстоящих сеанса и одно городское событие на эту дату. Это результат проверки, а не обещание постоянного количества записей.
- Есть проверка календарной даты Казахстана, происхождения ссылок, координат, времени, цены и свежести фидов. Неизвестная цена остается `null`, незаполненный торговый центр остается неизвестным.

Точный контракт находится в `lib/live-types.ts`. Карта отражает реальные координаты, но точность отдельного маркера зависит от источника POI. Ориентировочные координаты помечены. Расстояние до кинотеатра или площадки является расстоянием по прямой. Карта не строит пешеходную геометрию и не подтверждает доступность входа.

## Открытые источники без партнерских ключей

**Кино.** Адаптер читает доступные публичные страницы [Киноафиши Астаны](https://kz.kinoafisha.info/astana/movies/), сопоставляет видимое расписание с JSON-LD. Он принимает только сеансы с явной датой, временем и координатами соответствующего кинотеатра. Сюжет сокращается, постер сохраняет ссылку на источник. Это сторонний агрегатор, а не API кинотеатра, Ticketon или kino.kz. Подборка ограничена шестью фильмами и не представляет всю афишу города. Источник не публикует надежное время изменения каждой записи, поэтому `updatedAt` и `retrievedAt` означают время нашей загрузки, а `sourceUpdatedAt` остается `null`.

**События.** Адаптер использует публичную [афишу Astana.kz](https://astana.kz/ru/events). Он читает опубликованные карточки с явной датой и публичные JSON-данные, вложенные в SSR-страницу. JavaScript страницы не выполняется. Закрытые `/api` и `/bff` не вызываются. Доступные правила [robots.txt](https://astana.kz/robots.txt) проверяются перед сбором. Для площадки «Астана Арена» координаты проверяются по точному заголовку страницы Википедии через публичный MediaWiki API. Координаты являются точкой стадиона, а не входом. Другие площадки без подтвержденной привязки пока исключаются.

Фактический пример текущей проверки: [ФК Астана — ФК Каспий, Astana.kz](https://astana.kz/ru/events/e68bac9a-73d2-467c-a0bf-0e23d3690b1e). Время, нижняя граница цены и изображение происходят из этой публикации. Это не подтверждение свободных мест и не бронь.

Ticketon при прямом серверном чтении вернул очередь доступа. Проект не обходит ее и не подменяет получение данных результатами старого поискового индекса. Для стабильного партнерского доступа используются согласованные фиды. [Страница Ticketon для организаторов](https://ticketon.kz/en/organizer) описывает подключение по соглашению. У kino.kz есть партнерское направление, но публичный универсальный API сеансов с выданным проекту доступом не подтвержден. Внутренние сетевые методы сайтов не выдаются за разрешенный API.

Публичные адаптеры читают страницы при обращении, используют серверный кеш и могут перестать работать при изменении верстки или правил доступа. В таком случае интерфейс сообщает об отсутствии подтвержденных данных. Медиа не скачиваются в репозиторий. Ссылка на изображение не означает передачу прав на его дальнейшее использование. Для коммерческого показа нужно согласовать права и условия источника.

## Настройка Яндекс Карт

Установлен браузерный `YANDEX_MAPS_JS_API_KEY`. Значение не хранится в репозитории, но по назначению доступно браузеру через `/api/runtime-config`. В кабинете следует ограничить ключ необходимым JavaScript API и точным доменом `seruen-astana.connect550439.chatgpt.site`; локальный адрес разрешается отдельно для тестирования. Настройка секрета не подтверждает правильность кабинета, покрытие Астаны или право на бесплатную лицензию. Условия и риск для схожего сервиса рассматриваются отдельно, без автоматического утверждения одобрения Яндексом.

Карта после согласия использует собственные POI и явный набор управления: масштаб, полный экран, пробки. Другие продукты Яндекса не включаются этой настройкой. Серверный геокодер выключен, D1 не привязана (`null`), публичного геокодирующего маршрута нет. Его подготовленный ограничитель 900 попыток за 24 часа не относится к загрузкам JS-карты. При отсутствии ключа или отказе SDK используются доступные резервные карты.

Пробки Яндекса читаются из `traffic.provider.Actual.state` после `isInited`, целое `level` допускает **0–10**. Ноль не означает отсутствие данных. Балл не экспортируется в каталог или RAG. Казахский интерфейс приложения остается доступным, но `kk_KZ` не заявлен среди языков JS API 2.1. Приемка настоящего ключа, свежести балла и логотипов еще предстоит. [Подробная настройка](yandex-integration.md), [сравнение продуктов](yandex-products.md), [разбор условий](yandex-free-risks.md), [официальный SDK](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/dg/concepts/load), [Actual provider](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/ref/reference/traffic.provider.Actual).

## Настройка резервной карты 2GIS

1. Создайте аккаунт в Platform Manager и ключ для **Map Tiles API**, который нужен MapGL JS. Проверьте продукты и действующие лимиты своего тарифа. [Официальное начало работы](https://docs.2gis.com/en/mapgl/start/first-steps).
2. Создайте отдельный ключ, предназначенный для браузера. Включите ограничения Origin/Referer по фактическим заголовкам вашего приложения. Текущий адрес проекта: `https://seruen-astana.connect550439.chatgpt.site`. Для локальной проверки отдельно настройте используемый адрес `http://127.0.0.1:5173` или `http://localhost:5173`. Формат правила, схему и порт проверьте в панели. Не оставляйте ключ без ограничений. [Управление ограничениями ключа](https://docs.2gis.com/en/platform-manager/subscription/managing-keys).
3. Установите серверную переменную `TWOGIS_MAPGL_KEY` и перезапустите либо повторно разверните приложение. `/api/runtime-config` отдаст этот браузерный ключ клиенту. Это ожидаемое поведение: безопасность ключа обеспечивают ограничения продукта, домена и квоты.
4. После согласия пользователя SDK загружается с документированного `https://mapgl.2gis.com/api/js/v1`. Компонент включает `trafficOn: true`, `trafficControl` и слушает `trafficscore`. Поле события называется `score`. [Настройка слоя и управления](https://docs.2gis.com/en/mapgl/map/configuration/controls), [описание TrafficScoreEvent](https://docs.2gis.com/en/mapgl/reference/interface#trafficscoreevent).
5. Отсутствие события, недопустимый балл и значение старше пяти минут дают состояние «недоступно». После перемещения карты старый балл очищается до нового события. Диапазон 1–10 проверяется, ноль не превращается в «нет пробок». Доступность данных зависит от территории и продукта. [Ограничения покрытия пробок](https://help.2gis.ru/question/kak-posmotret-probki-na-dorogah).

MapGL отображает карту. Поиск организаций и маршрутизация являются отдельными продуктами. Если они нужны, оформите **Places API** и **Routing API**, храните их серверные ключи отдельно и соблюдайте разрешенные поля и квоты. Проект пока использует внешнюю ссылку для маршрута, а не эти API. [Places API](https://docs.2gis.com/en/api/search/places/overview), [Routing API](https://docs.2gis.com/en/api/navigation/routing/examples/routing).

Для OSM сохраняется обязательная атрибуция, отсутствуют массовая загрузка и предзагрузка тайлов. Публичные тайлы не предоставляют SLA для коммерческого трафика. Для массового использования выберите поставщика с подходящим тарифом. [Политика тайлов OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/).

## Подключение согласованных фидов

Переменные задаются на сервере, без префикса `NEXT_PUBLIC_`:

```env
YANDEX_MAPS_JS_API_KEY=
TWOGIS_MAPGL_KEY=
CINEMA_FEED_URL=
CINEMA_FEED_TOKEN=
EVENTS_FEED_URL=
EVENTS_FEED_TOKEN=
TRAFFIC_FEED_URL=
TRAFFIC_FEED_TOKEN=
```

URL задает администратор развертывания после согласования с владельцем данных. Клиент не может передать произвольный upstream URL. При наличии токена запрос использует `Authorization: Bearer ...`. Разрешены HTTPS и публичное DNS-имя без встроенных учетных данных. Перенаправления не следуются, приватные адреса и локальные хосты отклоняются. Развертывание должно дополнительно ограничить DNS/исходящий трафик известными поставщиками, если оно допускает недоверенных администраторов конфигурации.

`GET /api/runtime-config` возвращает только предназначенные для браузера ключи `yandexKey` и `twoGisKey`, выбор карты и логические признаки настроенных фидов. Он не возвращает адреса фидов, Bearer-токены, Telegram-токен, Instagram-токен, серверный ключ геокодера, подпись или ключ LLM.

Фид кино и событий представляет объект с полями `date` в формате `YYYY-MM-DD`, `timezone: "Asia/Qyzylorda"`, `source`, `updatedAt` и `items`. Все моменты времени требуют ISO 8601 с `Z` или явным смещением. Время в Казахстане соответствует локальному календарю, а не дате UTC. Поля записей перечислены в `lib/live-types.ts`. `distanceMeters` сервер пересчитывает самостоятельно. `priceIsFrom: true` означает минимальную цену «от», а `priceKzt: null` означает, что цена не подтверждена.

Для серверного фида пробок нужны те же поля даты, зоны, источника и обновления плюс `score` и `scale: 10`. В текущем контракте фида `score` должен быть целым баллом провайдера в диапазоне 1–10. Это отдельный контракт от браузерного балла Яндекса 0–10. Процент загруженности, скорость и цвета линий не конвертируются в балл.

| Источник | Допустимый возраст `updatedAt` | Серверный кеш |
| --- | --- | --- |
| Фид кино | 30 минут | 60 секунд |
| Фид событий | 6 часов | 5 минут |
| Фид пробок | 5 минут | 30 секунд |
| Публичные страницы кино/событий | Проверка даты сеанса на странице при загрузке, время изменения издателем неизвестно | 5 минут |

Для фидов проверяются также временные метки каждой записи. Сильное отклонение в будущее отклоняется. Неверная дата или истекшая свежесть дают `stale` и пустой набор. Ошибка сети или структуры дает `error`. Отсутствие настроенного источника дает `unconfigured`, если нет пригодного публичного адаптера. Ни один из этих статусов не заменяется вымышленными сеансами или значениями пробок.

## Telegram и Instagram

Прямые коннекторы этих платформ в приложении **не подключены**. Нормализованный `EVENTS_FEED_URL` позволяет принять проверенные публикации после настройки отдельного сервиса владельцем канала или аккаунта. Наличие ссылки на социальную сеть не означает, что данные уже поступают.

Для **Telegram** владелец создает бота через BotFather и добавляет его в свой канал с необходимым доступом. Bot API получает сообщения каналов, участником которых является бот. Прием новых `channel_post` и `edited_channel_post` организуется одним из способов: `getUpdates` с сохранением offset либо `setWebhook` с проверкой `X-Telegram-Bot-Api-Secret-Token`. Эти режимы не включаются одновременно. Произвольная история чужих каналов через Bot API недоступна. Публикация поста не равна дате события: ее нужно извлечь и проверить отдельно. [Telegram Bots FAQ](https://core.telegram.org/bots/faq), [Bot API](https://core.telegram.org/bots/api).

Медиа Telegram получает сервер с разрешением владельца. URL загрузки файла содержит токен бота и не должен попадать в публичный `imageUrl`. После проверки прав файл можно разместить на согласованном CDN, сохранив ссылку на исходный пост. Сам проект такие загрузки и сообщения сейчас не выполняет.

Для **Instagram** официальный API предназначен для профессиональных аккаунтов Business или Creator. Владелец создает Meta-приложение, добавляет Instagram API и проходит разрешенный OAuth-процесс своего аккаунта. Для пути Instagram Login используется разрешение `instagram_business_basic`. Обычный просмотр чужой публичной страницы не дает API-доступа к ее медиа. Путь Facebook Login требует связанной Facebook Page и другого набора разрешений. Список разрешений и доступ для внешних аккаунтов сверяются в App Dashboard и App Review. [Официальная коллекция Meta: Instagram Login](https://www.postman.com/meta/instagram/folder/1z5vxzu/instagram-api-with-instagram-login), [официальная коллекция Meta: Facebook Login](https://www.postman.com/meta/instagram/folder/u4g5a2a/instagram-api-with-facebook-login).

Токен, App Secret и обновление доступа остаются в отдельном серверном коннекторе. Он выбирает только одобренные владельцем медиа, хранит permalink и нормализует дату события. Не следует включать доступ к сообщениям, публикации и комментариям для простой афиши. Проверка текста и прав на фото нужна до включения записи в фид.

## Обновление, приватность и эксплуатация

Кеш текущей реализации находится в памяти экземпляра сервера и сбрасывается при перезапуске. Для стабильной нагрузки нужен общий кеш, ограничение частоты запросов и наблюдение за ошибками поставщиков. Отдельный upstream-сервис можно обновлять по расписанию в согласованной квоте, с backoff при HTTP 429 и обработкой отмен событий. Для собственных каналов пригодны webhooks. Автоматическое расписание в аккаунте пользователя этим проектом не создается.

Пользовательский интерфейс вызывает **POST** `/api/discover` с телом `{lat, lon, language}`, чтобы координаты не входили в URL обычного access-log. Совместимый GET оставлен для диагностики и не используется интерфейсом. Он не имеет отдельной роли администратора, поэтому для публичного развертывания при необходимости ограничьте диагностический доступ на периметре. Оба метода используют одинаковую проверку входа.

Координаты не передаются поставщикам афиши: сервер получает общий каталог Астаны и считает расстояние сам. Сервер приложения не создает историю запросов. Хостинг по-прежнему может видеть IP и тело запроса. В эксплуатационных журналах нужно отключить запись тел и удалить координаты из диагностических URL. Кеш не должен зависеть от координат устройства и не должен хранить их.

После согласия на карту браузер обращается к внешнему поставщику с IP и областью просмотра. Это отдельный обмен, который может косвенно раскрыть стартовую точку. Фотографии внешнего источника также создают запросы к его CDN при показе. Для усиления приватности используйте согласованный медиапрокси с удалением метаданных и ограниченным сроком кеша.

## Проверка

```sh
npm test
npm run check
node --experimental-strip-types scripts/collect-events.mjs
```

Последняя команда сохраняет фактический отчет в `data/events-collection-report.json`. Этот файл фиксирует проверку и не служит вечным «актуальным» резервным расписанием. Сеансы и события исчезают после смены даты или истечения актуальности. Для Яндекса установлен браузерный ключ, но реальная карта и пробки еще требуют приемки на разрешенном домене. 2GIS проверяется отдельно при наличии своего ключа. Эти проверки не подтверждают лицензионное одобрение сервиса.
