# Подготовка Яндекс Карт для Seruen

Проверено 18 октября 2026 года. Рекомендация по продуктам: [yandex-products.md](yandex-products.md). Условия, риски и черновик обращения в поддержку: [yandex-free-risks.md](yandex-free-risks.md).

## Текущее состояние

Яндекс **не подключён**: SDK не загружается, публичного геокодирующего маршрута нет, ключи не установлены, D1 в манифесте пока `null`. Текущая карта и самостоятельно собранный каталог работают как раньше. Получение ключа само по себе не включает запросы.

Подготовлены серверная политика, общий ограничитель и транспорт геокодера. Транспорт доступен только как внутренняя функция; он не вызывается из сайта, RAG или сборщиков. `GET /api/yandex/status` показывает состояние подготовки без ключей, адресов, IP и значений счётчиков.

## Ограничения кода

| Защита | Реализация |
| --- | --- |
| Общий бюджет | Не более 900 зарезервированных попыток за любые предыдущие 24 часа, на все серверы и ключи, использующие общую D1 |
| Частота | Между резервированиями минимум 1500 мс; отправка допустима только в течение 400 мс от начала резервирования, опоздавшая попытка сгорает |
| Один IP | До 60 попыток за любые 24 часа; это лимит сети, а не достоверная идентификация человека |
| Гонки запросов | Проверка и резервирование одной атомарной SQL-командой в D1 до внешнего HTTP-запроса |
| Ошибка счётчика | Запрет обращения к Яндексу, без резервного счётчика в памяти или localStorage |
| Повторы | Автоматических повторов нет; ошибка/таймаут провайдера не возвращает потраченную резервацию |
| Продукты | Разрешён к будущему подключению только геокодер; панорамы, поиск организаций, саджест, маршруты, матрица, изохроны, тайлы и локатор этим шлюзом отклоняются |
| HTTP | Фиксированный официальный хост, подписанный запрос, таймаут 6 секунд, запрет перенаправлений, ограничение размера ответа |
| Данные | Ответ не кешируется и не сохраняется в каталог, RAG, логи или БД; исходный ответ не переранжируется |
| Контекст | Транспорт требует явного согласия и контекста карты Яндекса; он не предназначен для OSM/2GIS или автоматического обогащения POI |

Лимит 900 — наш запас относительно опубликованных 1000 обращений геокодера в сутки, а не новый тариф Яндекса. Скользящее окно исключает двойной расход на границе суток. Ключи, их ротация и разные посетители не создают новые бюджеты в этой БД. Смена или удаление БД обнулит защиту: при восстановлении без последних 24 часов истории нужно держать обращения выключенными минимум 24 часа.

Счётчик учитывает только запросы, прошедшие через этот шлюз. Лимит Яндекса объединяет ключи одного продукта: другие сайты/сервисы того же аккаунта должны использовать общий счётчик или иметь согласованную отдельную долю бюджета. Поэтому требуется отдельное подтверждение выделенного бюджета. Браузерный ключ, прямые сторонние запросы и чужие потребители не контролируются этим сервером. Обещать абсолютную защиту любого опубликованного ключа нельзя.

## После получения ключа

1. Подтвердить бесплатный сценарий Seruen и применимую редакцию условий; в документах описан риск оговорки о схожих сервисах. Публичный доступ к демо необходим, но сам по себе не снимает остальные условия.
2. Для первого этапа выбрать JavaScript API с показом собственных POI. Если ввод адреса не нужен, отдельный геокодер можно не включать вообще. Браузерный ключ должен иметь только необходимые продукты и ограничения точного домена `qadam-astana-walks.connect550439.chatgpt.site`. Не разрешать весь домен `chatgpt.site`.
3. Для HTTP-геокодера использовать отдельный серверный ключ того же аккаунта. В кабинете включить **только подпись секретом и временем (WithTTL)**; опциональная подпись допускает неподписанные обращения и не обеспечивает такую защиту. Поддержка подписи указана в документации геокодера; фактическое включение и реакция на неподписанный запрос проверяются после получения ключа. Ограничения IP включать только при известном стабильном исходящем IP хостинга, а не по адресу компьютера разработчика.
4. Секрет подписи из кабинета и случайный секрет HMAC для счётчика — разные значения. Они хранятся только в секретах хостинга, без `NEXT_PUBLIC_*`, репозитория и клиентского конфига. Внешний ключ и подписанный URL нельзя писать в логи. Реальные API-ключи в чат не требуются.
5. При необходимости геокодера подключить общую D1: в `.openai/hosting.json` установить `d1: "DB"`, применить сгенерированную миграцию и проверить атомарные ограничения на тестовых запросах. Не использовать отдельную БД для каждого Worker/зеркала и не менять постоянную область счётчика.
6. Только после проверки установить серверные переменные из `.env.example`: разрешение геокодера, подтверждение лицензии, подтверждение выделенного бюджета, ключ, подпись и HMAC-секрет. Эти переменные пока недостаточны для запуска: публичный маршрут и рендерер карты ещё не соединены намеренно.
7. Добавить рендерер Яндекса после отдельного согласия посетителя. Не добавлять встроенные поиск, саджест, панорамы и маршрутизацию автоматически. Результаты Яндекса живут только в сеансе его карты и очищаются при смене провайдера; на резервную карту переходят только собственные POI.
8. Проверить Астану: позиционирование, входы, пробки и поддержку языков. Казахский интерфейс Seruen сохраняется, но перевод подписей карты/ответов API на казахский не обещается. Геокодер сейчас документирует русский/английский и ряд других языков, без гарантии `kk_KZ`.
9. Проверить сохранность логотипа, копирайтов и кнопки открытия Яндекс Карт на всех размерах экрана. Включить обработку отказа SDK и исчерпания квоты: сохранить собственные рекомендации и предложить выбрать точку вручную. Никакого автоматического перехода на платный тариф.

При лимите по IP посетители общего Wi-Fi могут получить отказ совместно. Это осознанный компромисс защиты квоты; после оценки нагрузки его можно пересмотреть, сохранив общий потолок. Бот способен исчерпать доступную квоту и ухудшить доступность, но не должен увеличить число разрешённых попыток. Перед публичным геокодером понадобятся ограничения запросов на edge и проверка того, что IP берётся из доверенного заголовка Cloudflare, а не из тела запроса или `X-Forwarded-For`.

Псевдонимизированные HMAC IP в счётчике всё ещё требуют аккуратного обращения. В БД нет сырых IP, текстов поиска, координат и ответов Яндекса. Очистка служебных записей старше 48 часов выполняется после обработки попытки, а не перед её отправкой; ошибки очистки не дают дополнительные разрешения. Для удаления при отсутствии трафика оператору потребуется отдельный запуск очистки.

## Проверки

Тесты проверяют отключённую конфигурацию, запрет неподдерживаемых продуктов, конкурирующие резервации в настоящем SQLite, глобальный и IP-потолок, отсутствие сброса при ротации ключа, ошибку БД, отсутствие повторов, подпись и непередачу ключа в результат. Они не заменяют проверку настоящего ключа и настроек кабинета.
