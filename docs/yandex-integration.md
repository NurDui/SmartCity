# Яндекс Карты в Seruen и подготовка геокодера

Проверено 18 октября 2026 года. Рекомендация по продуктам: [yandex-products.md](yandex-products.md). Условия, риски и черновик обращения в поддержку: [yandex-free-risks.md](yandex-free-risks.md).

## Текущее состояние

Браузерная карта Яндекса **настроена**: `YANDEX_MAPS_JS_API_KEY` установлен средствами секретов хостинга и не записан в репозиторий. Это предназначенный для браузера ключ: `/api/runtime-config` передает его клиенту, поэтому ограничение домена и продуктов в кабинете обязательно. Браузерная проверка нового домена подтвердила отрисовку Астаны, собственных маркеров и слоя пробок. SDK при этом сообщил `Invalid API key`; корректность активации и ограничений ключа в кабинете не подтверждена. Свежий числовой балл в этой проверке не получен и не выдумывается. Статус настройки не означает одобрение бесплатного сценария Яндексом.

Порядок выбора по наличию ключей: **Яндекс → 2GIS → OpenStreetMap**. При ошибке инициализации выбранного SDK включается непосредственно OpenStreetMap; промежуточная попытка 2GIS не выполняется. Внешний SDK и тайлы загружаются только после отдельного согласия посетителя. На резервную карту передаются собственные POI и стартовая точка; результаты геокодирования Яндекса не используются.

В карте Яндекса показываются собственные маркеры каталога. Элементы управления заданы явно: масштаб, полный экран и пробки. Поиск организаций, саджест, геолокация Яндекса, панорамы и построение маршрута не вызываются. Определение точки устройства выполняет браузер только по действию пользователя; внешняя ссылка «Маршрут в 2GIS» открывает отдельный сайт, а не Routing API Яндекса.

Серверный геокодер остается **выключенным**: разрешающий флаг не включен, D1 в манифесте `null`, публичного маршрута геокодирования нет. Подготовлены политика, общий ограничитель и внутренний транспорт, не вызываемые из сайта, RAG или сборщиков. Браузерный ключ карты не заменяет отдельный серверный ключ геокодера. `GET /api/yandex/status` сообщает состояние карты и этой подготовки без ключей, адресов, IP и значений счетчиков.

## Пробки и языки браузерной карты

Баллы поступают только из SDK. Для Яндекса используется `traffic.provider.Actual.state`: после `isInited` принимается целое `level` **0–10**. Ноль является допустимым значением и не должен теряться как ложное значение. 2GIS использует другой контракт: событие `trafficscore`, `score` **1–10**. Серверный согласованный фид пока также принимает 1–10; результат Яндекса не записывается в этот фид и не пересчитывается из цвета линий. Покрытие и фактическое получение свежего балла для Астаны с установленным ключом остаются предметом приемки. [Официальный Actual provider](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/ref/reference/traffic.provider.Actual).

Интерфейс Seruen сохраняет русский, казахский и английский. Список языков JavaScript API 2.1 не содержит `kk_KZ`; казахские подписи SDK не обещаются. Язык приложения и язык картографического SDK — разные настройки. [Загрузка и языки SDK](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/dg/concepts/load).

## Ограничения подготовленного серверного геокодера

Следующая таблица относится только к будущим запросам через серверный геокодирующий шлюз. Лимит 900 не применяется к загрузкам браузерной JS-карты и не контролирует произвольные обращения опубликованного браузерного ключа.

| Защита | Реализация |
| --- | --- |
| Общий бюджет | Не более 900 зарезервированных попыток за любые предыдущие 24 часа, на все серверы и ключи, использующие общую D1 |
| Частота | Между резервированиями минимум 1500 мс; отправка допустима только в течение 400 мс от начала резервирования, опоздавшая попытка сгорает |
| Один IP | До 60 попыток за любые 24 часа; это лимит сети, а не достоверная идентификация человека |
| Гонки запросов | Проверка и резервирование одной атомарной SQL-командой в D1 до внешнего HTTP-запроса |
| Ошибка счётчика | Запрет обращения к Яндексу, без резервного счётчика в памяти или localStorage |
| Повторы | Автоматических повторов нет; ошибка/таймаут провайдера не возвращает потраченную резервацию |
| Продукты | Разрешён к будущему подключению только геокодер; панорамы, поиск организаций, саджест, маршруты, матрица, изохроны, тайлы и локатор этим шлюзом отклоняются |
| HTTP | Фиксированный официальный хост, подписанный запрос, таймаут 6 секунд, запрет перенаправлений, ограничение размера ответа |
| Данные | Ответ не кешируется и не сохраняется в каталог, RAG, логи или БД; исходный ответ не переранжируется |
| Контекст | Транспорт требует явного согласия и контекста карты Яндекса; он не предназначен для OSM/2GIS или автоматического обогащения POI |

Лимит 900 — наш запас относительно опубликованных 1000 обращений геокодера в сутки, а не новый тариф Яндекса. Скользящее окно исключает двойной расход на границе суток. Ключи, их ротация и разные посетители не создают новые бюджеты в этой БД. Смена или удаление БД обнулит защиту: при восстановлении без последних 24 часов истории нужно держать обращения выключенными минимум 24 часа.

Счётчик учитывает только запросы, прошедшие через этот шлюз. Лимит Яндекса объединяет ключи одного продукта: другие сайты/сервисы того же аккаунта должны использовать общий счётчик или иметь согласованную отдельную долю бюджета. Поэтому требуется отдельное подтверждение выделенного бюджета. Браузерный ключ, прямые сторонние запросы и чужие потребители не контролируются этим сервером. Обещать абсолютную защиту любого опубликованного ключа нельзя.

## Эксплуатация карты и возможное включение геокодера

1. Подтвердить бесплатный сценарий Seruen и применимую редакцию условий; в документах описан риск оговорки о схожих сервисах. Публичный доступ к демо необходим, но сам по себе не снимает остальные условия.
2. Уже выбран JavaScript API с показом собственных POI. Если ввод адреса не нужен, отдельный геокодер можно не включать вообще. В кабинете оставить браузерному ключу только необходимые продукты и ограничения точного домена `seruen-astana.connect550439.chatgpt.site`. Не разрешать весь домен `chatgpt.site`. Для локальной приемки нужен отдельно разрешенный тестовый Origin/Referer; само присутствие ключа не подтверждает настройку кабинета.
3. Для HTTP-геокодера использовать отдельный серверный ключ того же аккаунта. В кабинете включить **только подпись секретом и временем (WithTTL)**; опциональная подпись допускает неподписанные обращения и не обеспечивает такую защиту. Поддержка подписи указана в документации геокодера; фактическое включение и реакция на неподписанный запрос проверяются после получения ключа. Ограничения IP включать только при известном стабильном исходящем IP хостинга, а не по адресу компьютера разработчика.
4. Секрет подписи из кабинета и случайный секрет HMAC для счётчика — разные значения. Они хранятся только в секретах хостинга, без `NEXT_PUBLIC_*`, репозитория и клиентского конфига. Внешний ключ и подписанный URL нельзя писать в логи. Реальные API-ключи в чат не требуются.
5. При необходимости геокодера подключить общую D1: в `.openai/hosting.json` установить `d1: "DB"`, применить сгенерированную миграцию и проверить атомарные ограничения на тестовых запросах. Не использовать отдельную БД для каждого Worker/зеркала и не менять постоянную область счётчика.
6. Только при необходимости геокодера и после проверки установить отдельные серверные переменные из `.env.example`: разрешение геокодера, подтверждение лицензии, подтверждение выделенного бюджета, ключ, подпись и HMAC-секрет. Браузерная карта их не включает. Эти переменные пока недостаточны для запуска геокодирования: публичный маршрут отсутствует намеренно.
7. Сохранять отдельное согласие перед загрузкой рендерера Яндекса и явный список элементов управления. Не добавлять поиск, саджест, геолокацию, панорамы и маршрутизацию автоматически. Если геокодер появится позднее, его результаты должны жить только в сеансе карты Яндекса и очищаться при смене провайдера; сейчас их нет.
8. Проверить Астану: позиционирование, входы, пробки и поддержку языков. Казахский интерфейс Seruen сохраняется, но перевод подписей карты/ответов API на казахский не обещается. Геокодер сейчас документирует русский/английский и ряд других языков, без гарантии `kk_KZ`.
9. Проверить сохранность логотипа, копирайтов и кнопки открытия Яндекс Карт на всех размерах экрана. Включить обработку отказа SDK и исчерпания квоты: сохранить собственные рекомендации и предложить выбрать точку вручную. Никакого автоматического перехода на платный тариф.

При лимите по IP посетители общего Wi-Fi могут получить отказ совместно. Это осознанный компромисс защиты квоты; после оценки нагрузки его можно пересмотреть, сохранив общий потолок. Бот способен исчерпать доступную квоту и ухудшить доступность, но не должен увеличить число разрешённых попыток. Перед публичным геокодером понадобятся ограничения запросов на edge и проверка того, что IP берётся из доверенного заголовка Cloudflare, а не из тела запроса или `X-Forwarded-For`.

Псевдонимизированные HMAC IP в счётчике всё ещё требуют аккуратного обращения. В БД нет сырых IP, текстов поиска, координат и ответов Яндекса. Очистка служебных записей старше 48 часов выполняется после обработки попытки, а не перед её отправкой; ошибки очистки не дают дополнительные разрешения. Для удаления при отсутствии трафика оператору потребуется отдельный запуск очистки.

## Проверки

Тесты серверной подготовки проверяют отключенную конфигурацию, запрет неподдерживаемых продуктов, конкурирующие резервации в настоящем SQLite, глобальный и IP-потолок, отсутствие сброса при ротации ключа, ошибку БД, отсутствие повторов, подпись и непередачу серверного ключа в результат. Они не заменяют проверку настоящего ключа и настроек кабинета.

Браузерная приемка карты должна отдельно подтвердить отсутствие запросов к Яндексу до согласия, загрузку на разрешенном домене, собственные маркеры, масштаб/полный экран/пробки, видимую атрибуцию, отказоустойчивость и отсутствие незаявленных геокодирующих, поисковых и маршрутных обращений. Пока эта приемка не завершена, карта отмечена как настроенная, а не подтвержденно работающая с настоящим ключом.
